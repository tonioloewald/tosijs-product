## Blockers

### B1 — The doc site publishes inert prerendered markup *(correctness; verified)*
`demo/site.ts:10`

tosijs-ui 1.14.1 (tosijs-ui#133) deliberately stopped re-exporting the doc-system cluster from the barrel — the header comment in `node_modules/tosijs-ui/dist/index.js` says so explicitly. `demo/site.ts` still does only `import "tosijs-ui"`, so the built bundle lost the doc system entirely.

Measured in this triage, not inferred: in `docs/hydrate.js`, `tosi-doc-system` goes **25 → 1** against `v0.7.0` (and the single survivor is this file's own `querySelectorAll("tosi-doc-system")` string, not a registration), `tosi-example` **11 → 0**, `doc-navbar` **5 → 0**. `customElements.get("tosi-doc-system")` is `false` on the committed tree; pages fall back to the `:not(:defined)` static layout — no nav, no header, no theme toggle, no Source/maximize. GitHub Pages serves `docs/` from `main`, so tagging publishes the broken site, and the release's marquee new page (Owl Pro) is the most visible casualty. One doc has an executable ```js fence that will now render as plain text.

**Fix:** add `import 'tosijs-ui/doc-browser'` and `import 'tosijs-ui/live-example'` to `demo/site.ts`, rebuild, re-commit `docs/`.
**Re-review scope:** correctness + blast radius over the remediation diff — which includes the fully regenerated `docs/` tree, not just `demo/site.ts`. A browser check of at least `/` and `/owl-pro/` from the rebuilt output is part of it.

### B2 — Shipped `.d.ts` require `tosijs@^1.10.0`, but the declared peer floor is `^1.9.1` *(blast radius; verified)*
`package.json:43`

Six of seven shipped declaration files do `import { Component, type ComponentAttrs } from "tosijs"`. `ComponentAttrs` landed in tosijs **1.10.0**; it is absent from the whole of 1.9.1/1.9.2. A consumer on 1.9.x satisfies the declared peer, installs with no warning, and gets `TS2305: Module 'tosijs' has no exported member 'ComponentAttrs'` on every type import of this package. It typechecks here only because the lockfile resolves 1.10.1.

`skipLibCheck: true` suppresses the errors but then degrades the merged interface to `any` — silently destroying the typing this release's own "Fixed" entry celebrates.

**Fix:** raise peer **and** dev `tosijs` to `^1.10.0`, re-lock, re-run `bun tsc --noEmit` and `release-doctor`.
**Re-review scope:** Tier 0 only — a range bump plus lockfile, no behavioral surface change.

### B3 — The CDN IIFE dropped 8 element registrations; that removal *is* the headline size win, and it is undocumented *(completeness, promoted; confirmed in triage)*
`CHANGELOG.md`, `src/docs/getting-started.md:7`

`tosi-*` tag literals in `dist/index.js` go 81 → 73 against `v0.7.0`. Gone: `tosi-code`, `tosi-css-var-editor`, `tosi-doc-system`, `tosi-doc-system-prefs`, `tosi-example`, `tosi-line-offset-probe`, `tosi-test-results`, `tosi-tests-done` — I confirmed `tosi-code`, `tosi-example` and `tosi-doc-system` are each **0 occurrences** in the committed `dist/index.js`. The CHANGELOG presents 578,618 → 145,051 gz as pure upside and never says the bundle stopped shipping components, while `src/docs/getting-started.md:7` still claims "a single script tag gives you everything — tosijs, tosijs-ui, and tosijs-product with all custom elements registered". Anyone loading the jsDelivr IIFE for `<tosi-code>` or `<tosi-example>` breaks on upgrade with no notice.

This is the same defect class as 0.7.0's B2 (breaking changes missing from the Breaking section), which was a blocker then.

**Fix:** add a `### Breaking` entry naming the eight elements and pointing CDN consumers at the tosijs-ui subpaths; correct `getting-started.md:7`.
**Re-review scope:** documentation accuracy over the remediation diff.

## Majors (verified; fix soon, neither blocks alone)

### MJ1 — `--stop` SIGTERMs a pid it never positively identifies *(blast radius; verified)*
`bin/site.ts:96`

`currentHolder()` validates the lock only with `process.kill(pid, 0)` — liveness, not identity. The lock is not cleaned up on SIGKILL/OOM/power loss and lives in the system tmpdir; the verifier found **four** `tosijs-build-*.lock` files on this machine right now, two naming dead pids (one nine days old), and observed the pid counter wrap past 99999 within an hour. Planting a lock naming a live unrelated pid makes `currentHolder` hand it back for signalling. Upstream's own port-reclaim path sets the standard two files away (`dev-server.js:382-426` checks `ps -p PID -o comm=` then the process cwd, with the comment "'A JS runtime' is not 'OUR dev server', and only the second earns a signal (#77)").

Same three lines carry two more defects, merged here: it does not check `holder.role`, so `bun run stop` SIGTERMs an in-flight `bun run build` mid-`rm -rf docs/` (the exact failure the lock exists to prevent); and the success path prints `Stopped ${describeHolder(holder)}`, which renders the *refusal* banner — a successful stop tells the reader the server is still running and they should stop it. Strong evidence this path was never executed.

**Fix:** cross-check pid identity against the lock record before signalling; gate on `holder.role === 'dev-server'` and exit non-zero otherwise; print a one-line receipt on **stderr** naming what was signalled and for which project; distinguish ESRCH from EPERM in the catch.

### MJ2 — tosijs-ui's guard against exactly B1 false-negatives on this repo *(correctness; verified)*
`demo/site.ts:14`

`bundleRegistrations(src) => ({ docSystem: src.includes('tosi-doc-system'), ... })` (`host-preset.js:111`) is a bare substring grep. `demo/site.ts` contains the literal `tosi-doc-system` inside `document.querySelectorAll("tosi-doc-system")`, so the check passes while nothing is registered — the one adopter shape the grep cannot distinguish is the shape this repo has. Worse than silent: with `docSystem: true` / `liveExample: false` the build fired the *live-example* warning instead, misdiagnosing the failure and pointing the author at the wrong import.

Per gate 6: **every prior "the site builds fine" green obtained from this build is unverified** and needs a browser check, not build output. Upstream half is routed below; locally, the real `doc-browser` import also satisfies the grep, so fixing B1 moots the false negative here.
