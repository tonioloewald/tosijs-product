## Per-lens summary

**correctness (6 findings, 2 verified)** — Nothing wrong in the scroll engine itself. The cluster is on the edges: `bin/tosi-mosaic.ts` maps `--quality` backwards for PNG (verified by measurement, 9.8× file-size spread in the wrong direction with byte-identical pixels), `src/tosi-prism.ts` guards its "closed allowlist" with a truthiness test over a prototype-bearing object literal, `loadScript` latches rejected promises forever now that a 10s timeout can produce them, and `isColor`'s prefix test silently widens the documented `rgb()`/`hsl()` breaking change to *any value starting with a color* — I reproduced that one directly: `interpolateStrings("rgb(0,0,0) 0 0 10px", "rgb(0,0,0) 0 0 20px", 0.5)` → `color-mix(in srgb, rgb(0,0,0) 0 0 10px 50%, rgb(0,0,0) 0 0 20px)`, invalid CSS, so a `box-shadow` waypoint pair drops its shadow for the whole pin interior.

**blast-radius (7 findings, 3 verified)** — The one that matters most is not code at all: the doc site still serves the truncated mosaic the tool fix was written for. Beyond that, the new SRI table is correct but *fails open* on widening; `rm -rf dist` traded a stale-declaration hazard for a missing-declaration one behind four `.nothrow()` calls; and two release-notes claims (the sourcemap one, the mosaic-regeneration silence) are contradicted by what's actually deployed.

**ecosystem (1 finding, unverified)** — Adding `haltija` as a devDep demoted the hoisted `tosijs-schema` from 1.8.1 to 1.5.1. Contributor-machine scope only; consumers never install devDeps.

**practices (1 finding, unverified)** — The `@0.7.0` CDN pins in `README.md` and `src/docs/getting-started.md` are hand-maintained with nothing checking them; the shared `release-doctor` is the right home for that rule.

**Not exercised this pass:** nobody opened the deployed doc site in a browser. That was already flagged in `reviews/0.7.0-remediation-re-review.md` and is still true — see *Completeness gaps*.

## Strongly recommended before you tag (not blockers, but cheap and visible)

### 1. The shipped mosaic is truncated — verified (major, blast-radius)

`demo/assets/agent-owl_10x10_100.jpg` was generated by the *broken* `tosi-mosaic` and never regenerated. Verified independently: `agent-owl.mp4` has 192 frames; the mosaic is 6400×3600 = 10×10 tiles of 640×360; SSIM of the last tile against the video is **0.964 at frame 99** and **0.063 at frame 191**. So the filmstrip covers frames 0–99 — the first 52% of the 8-second clip — while the filename and the README's `total="100"` claim the whole video. `docs/agent-owl_10x10_100.jpg` is byte-identical (md5 `c5c4a890...`), so this is what GitHub Pages serves.

It's referenced in `README.md:112`, `src/tosi-filmstrip.ts:13` and `:43`, and the built `demo/docs.json`. The README scene *immediately before* it scrubs the full clip via `data-scroll-animate="currentTime"`, so two adjacent scenes disagree about where the clip ends — on a page that says "This page is the demo," and this is the recipe adopters copy.

Regeneration note from the verifier: `-f 100` now yields stride 1 → 192 frames in a 14×14 grid at 8960×5040 (much larger). **`-f 96` gives stride 2, total 96, still a 10×10 grid, covers the whole clip at today's file size** — that's the one you want. The TODO item about shrinking this 4.9MB eagerly-fetched asset can ride along.

### 2. Decide the `docs/version.json` loop rather than re-checking it — verified (minor, correctness)

Committed content stamps `9b98544` while committed `docs/` was built from `54f33f9`; the working tree holds the corrected stamp, uncommitted. This is verbatim the "Must clear before tagging" item from the last re-review, recurring — and **it cannot be cleared by committing**: `node_modules/tosijs-ui/dist/doc-system/site/build-stamp.js` stamps `git rev-parse --short HEAD` at *build* time, which is always the parent of the commit containing the output. Every build→commit cycle names its own parent. `git diff 9b98544...HEAD -- docs/version.json` shows `b8808ee → 9b98544`, i.e. the previous release did exactly the same thing.

The tree *can* be made clean (`git checkout -- docs/version.json` accepts the parent stamp, which is what the design intends) — only *convergence via committing rebuilds* is impossible. Upstream documents this as accepted behaviour and says the warning belongs at deploy time. Pick one: gitignore the file, stamp the tag instead of HEAD, or accept the lag and delete the checklist item.

## Follow-ups by destination

### → `TODO.md` (this repo: correctness / dx / coverage)

- [ ] **`tosi-mosaic --format png` maps `--quality` backwards** (`bin/tosi-mosaic.ts:186`, verified). `9 - q/100*9` means `-q 100` → `-compression_level 0` (largest file) and `-q 0` → level 9, while the help text this same diff rewrote says "higher is better". PNG is lossless — measured: q0=532,102 B, q95/q100=5,200,931 B, **identical decoded-pixel md5 at every level**. The default also regressed: `-q:v 75` was inert (ffmpeg used level 6); the new default is level 2, +2.2% on real footage (`agent-owl.mp4`), +12.2% on flat synthetic. The user who follows the help text pays +70% for byte-identical pixels. Fix: ignore `--quality` for png (or invert the mapping) and say in the help that for png the flag trades size against encode time, not fidelity. Note the code comment at `:171-176` already says exactly this and the mapping was wired inverted anyway.
- [ ] **CHANGELOG's "verified monotonic (q30/75/95 → 1.9MB/3.4MB/6.6MB)" is jpg-only.** The verifier's jpg run reproduces those ratios (1 : 1.75 : 3.15 vs the claimed 1 : 1.79 : 3.47); png cannot produce them (542KB → 608KB → 8.5× jump). Record which format the numbers came from, or re-measure per format — as written the entry blesses both encoders on one jpg measurement.
- [ ] **Add a CHANGELOG line telling users to regenerate old mosaics.** The code fix does not propagate to already-emitted assets: anyone who ran `tosi-mosaic` before this fix on a source with fewer than 2× the requested frames has a truncated asset deployed, and nothing in the release notes says so. (`CHANGELOG.md:74-80` documents the bug, not the remediation.)
- [ ] **`LANGUAGE_DEPS` guard is a truthiness test over a prototype-bearing object** *(unverified — sanity-check before acting; the code shape is confirmed by inspection)* (`src/tosi-prism.ts:199`). `const deps = LANGUAGE_DEPS[lang]; if (!deps) return;` lets `constructor`, `toString`, `valueOf`, `hasOwnProperty`, `__proto__` sail through to `for (const d of deps)`. A ```` ```constructor ```` fence would make `loadPrism()` reject, so `highlightCodeBlocks()` rejects and *no* block on the page highlights. Use `Object.hasOwn(...)` or `Object.create(null)`. **Same hole in `resolveLanguage`** at `:183` — `LANGUAGE_ALIASES[name] ?? name` uses `??`, which only falls back on null/undefined, so `resolveLanguage("constructor")` returns a *function object*, not a string.
- [ ] **`loadScript` caches rejected promises forever** *(unverified; `loaded.set(path, p)` at `src/tosi-prism.ts:119` is unconditional and nothing evicts — confirmed by inspection)*. With the new `LOAD_TIMEOUT_MS` (10s) a merely-slow load now latches: the promise rejects, the script tag finishes a second later so `globalThis.Prism` exists, but every later `loadPrism()` rejects instantly. `loaded.delete(path)` before `reject` in **both** the timeout and `onerror` paths. Note the theme half of this diff got the failure mode right (resolves on failure); the script half regressed.
- [ ] **`TosiPrism.connectedCallback` never catches `_highlight`** *(unverified; `this._highlight()` at `src/tosi-prism.ts:276` is unawaited and uncaught — confirmed by inspection)*. Every new reject path (CDN outage, 10s timeout, integrity mismatch after a `PRISM_VERSION` bump) surfaces as an unhandled rejection **and** bare unwrapped text, because `_highlight` returns before building the `<pre><code>`. The graceful-degradation branch already exists (`escapeHtml` → `data-prism-highlighted="false"`); it's just unreachable when the load rejects. Wrap the `await loadPrism([lang])` in try/catch and fall through. *This is the one item from the re-review's bullet that did not land.*
- [ ] **Make the SRI allowlist fail closed** (`src/tosi-prism.ts:100`, major). `if (integrity) { s.integrity = ...; s.crossOrigin = ... }` — add `python: []` to `LANGUAGE_DEPS` (the documented obvious feature request) and the script goes out unpinned with no error, no warning, no test. The comment above `LANGUAGE_DEPS` names it a security boundary; nothing enforces it. Throw for any path under `CDN` with no hash entry.
- [ ] **`isColor`'s prefix test captures compound values** (`src/waypoints.ts:36`, reproduced this pass). `box-shadow: rgb(0,0,0) 0 0 10px` → `…20px` now emits invalid `color-mix()`, the declaration is dropped, and the shadow vanishes for the whole pin interior, snapping back at t=1. These interpolated per-number before the kernel unification. Tighten to a complete-color regex (`/^(#[0-9a-f]{3,8}|(rgba?|hsla?|color|oklch|oklab|lab|lch)\([^)]*\))$/i` + the named list) so compound values fall back to the numeric path. **If that's too large for this tag:** widen the CHANGELOG's Breaking bullet to "any value *beginning with* a color token" and add a test pinning the compound case, so the scope is visible to whoever hits it.
- [ ] **Add a post-condition to `buildLibrary()`** (`bin/site.ts:33`, verified). `rm -rf dist` then four `.nothrow()` steps with nothing asserting the artifacts exist. `Bun.build` *does* throw (verified on bun 1.4.0), so the exposed steps are `tsc`/`mv`/`rm`. A hard tsc failure (missing typescript, unparseable tsconfig, OOM) leaves `dist/` with the two bundles and no `.d.ts`; `files: ["dist/*.d.ts"]` then matches nothing, npm packs silently (reproduced: exit 0, no warning), and the tarball ships `types: "dist/index.d.ts"` pointing at nothing. Before the clean step, stale-but-present declarations would have packed. Three lines closes it: `if (!(await Bun.file("dist/index.d.ts").exists())) throw`. *Qualifier worth knowing:* `tsconfig.json` sets no `noEmitOnError`, so an ordinary type error still emits — you need a harder failure to reach the empty state, and `prepublishOnly`'s typecheck gates most of those. Low probability, severe consequence.
- [ ] **Scope the dev-server watch hook to `buildSite` only** (`bin/site.ts`). `devServer(siteConfig, { build: buildAll })` routes every watch rebuild through `buildLibrary()`'s `rm -rf dist`, so ordinary development deletes and regenerates **ten tracked files on every save**, with a (trivially recoverable) window where Ctrl-C leaves `dist/` missing. `buildSite`'s last-good stash protects `outputDir` only, not `dist/`. The TODO already proposes this change for the RSS reason.
- [ ] **Fix the mosaic ordinal** (`bin/tosi-mosaic.ts:153`, nit). `stride === 2 ? "nd" : stride === 3 ? "rd" : "th"` prints "every 21th frame" at stride 21, and "every 1 frame" for the no-op. Sidestep it: "taking every frame" for stride 1, "taking 1 frame in ${stride}" otherwise. Cosmetic — `total` is correct.
- [ ] **The sourcemap claim in the release notes is false** (`CHANGELOG.md:64`). "Dev only — never bundled, never in `docs/`." Verified: `docs/hydrate.js` and `docs/iife.js` contain zero "haltija" (the executable half holds), but `docs/hydrate.js.map` (1.8MB) and `docs/iife.js.map` (4.4MB) both do, and both are committed and Pages-served. Exposure is low (no token, no endpoint, tosijs-ui's own source text) — the *assertion* is the finding. Either stop shipping `docs/**.map` (6.2MB of the published payload; the TODO already asks) or narrow the sentence to "never in the emitted JS; the sourcemaps still carry tosijs-ui's dev-only source text."
- [ ] **Test coverage for `src/tosi-prism.ts` — currently zero.** The TODO lists two cases (exact URL set for `['javascript']`; nothing loaded for `['../../evil/x']`). Add two more that catch what those miss: `['constructor']` (the prototype hole), and `keys(SUBRESOURCE_INTEGRITY) === {core} ∪ {prism-<k> for k in LANGUAGE_DEPS} ∪ {theme}` — the latter is the one that catches both a widened `LANGUAGE_DEPS` and a `PRISM_VERSION` bump that forgot to regenerate hashes.
